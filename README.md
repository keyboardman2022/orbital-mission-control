# ORBITAL · 引力之外

## 正式卫星控制台（已实现）

运行环境：Node.js 24.13.0 已实测。使用内置 `node:sqlite`，该版本会显示 ExperimentalWarning；无需 npm install。

```powershell
cd D:\Codex\orbital
npm start
```

打开 http://127.0.0.1:4174/ 进入 3D 星图，可使用经典地图或生成 3D 种子地图。旧的任务控制书签会跳转到经典 3D 星图。

在任务控制台点击「种子地图」，可自定义星系、黑洞和恒星数量，再进入对应地图发射。控制台地址会保留地图，刷新可以继续查看该地图的卫星和历史轨迹。

新版种子地图在三维空间内分布星系，并为各自的轨道留出间距。锁定数量时，种子会优先保留其他可行的随机结果。同一种子、选项和布局版本会生成同一张地图。从已保存的地图进入预览，保留种子和数量即可返回原地图。

新生成的 3D 地图会抽取每个天体的初始三维位置、速度和方向。进入后，服务器按带近距离软化的牛顿引力计算天体之间的运动与合并。卫星是单向受力的试验粒子，其填写质量不会改变任何轨迹。星图上方的「天体历史轨迹」可以选取天体并拖动时间轴，合并前后的天体各有自己的轨迹。已有种子地图保留各自的动力学版本。

暂停按钮旁可切换 1×、2×、4× 或 8× 模拟速度。倍率按当前账号和地图保存，暂停时也可以设置。天体与卫星继续使用相同的积分步长，历史回放有自己的播放速度。

种子预览的「引力实验场」可生成 2–48 个天体，随机选取三维初始位置、速度、种类与质量。实验使用牛顿多体积分与近距离软化，接触时按质量和动量合并。相同种子与数量可重跑同样的初始条件。实验运行在浏览器，和正式星图的档案分开。

从星图切换到另一张地图时，当前账号在原图的卫星、天体轨迹和服务器导出会自动清除。预览、刷新和进入同一张地图会保留记录。公共种子仍可用于重新进入原图。

### Windows 双击启动

项目根目录提供 `ORBITAL.exe`。双击后会检查本机服务：若服务已经运行则直接打开任务页面；否则自动查找 `D:\node\node.exe`、项目内 `node.exe` 或 PATH 中的 Node，在后台启动服务，健康检查通过后打开浏览器。启动失败时会弹出原因，后台日志保存在 `data/server.launcher.log`。

启动器必须保留在项目根目录。修改启动器源码后，可在 PowerShell 中运行 `tools\build-launcher.ps1` 重新生成；`ORBITAL.exe --check` 仅检查项目结构和 Node，`ORBITAL.exe --no-browser` 启动服务但不打开浏览器。

- 星图保留旋转吸积盘、恒星光球和捕获效果。暂停模拟会冻结当前 3D 地图上的天体和卫星，继续时从同一位置恢复。
- 选择基准天体，输入相对 X、Y、Z 坐标、质量、初速度、方向角和俯仰角。发射辅助标记实时显示位置和速度方向。
- 访客身份通过 HttpOnly 会话保存。首次出现的恢复密钥可下载保存，跨设备恢复档案；也可主动轮换密钥。密钥持有者可以访问和终止该身份的卫星，请私密保存。
- SQLite 保存出生档案、轨迹、关键事件与恢复状态。关闭浏览器后，只要本机服务仍运行就继续计算；服务停止或电脑关闭时冻结模拟时间，下次启动从最后保存的进度继续，不补算离线时段。新发射立即运行，旧版本留下的排队卫星在启动时直接开始计算。
- 隐藏卫星只影响显示。终止卫星后仍可回放和导出它的轨迹。
- 回放读取归档点并插值显示，CSV/JSON 导出固定截止 tick 和记录序号；CSV 第一条数据的 `metadata_json` 列包含模型、单位、采样方法与事件元数据。
- 实时画面最多绘制最近 100 个对象并保留当前选中对象；较老的对象可分页选择并继续订阅。回放提供完整生命时间轴，按需读取当前位置附近最多20模拟秒的窗口，缓存上限8000点；导出不受显示窗口限制。
- 后台初始容量保护为 1000 个并发活跃/排队对象，可通过 `ORBITAL_MAX_ACTIVE` 配置；不限制累计发射次数。达到容量时明确拒绝新请求，保留已有轨迹。正式容量取决于硬件和采样密度，需要实测调整。

### 时间、单位和误差

正式控制台输入采用 **km、km/s、kg**，发射坐标以所选基准天体为原点。明确假设中央黑洞质量为 **10 倍标称太阳质量**，不是对某个实测黑洞的标定。由 IAU 2015 B3 的标称太阳质量参数 `(GM)☉ = 1.3271244×10²⁰ m³/s²` 和光速 `c = 299792458 m/s`，按 `r_s = 2GM/c²` 得到视界半径约 **29.5325 km**。场中另有九颗大小、质量和颜色各异的预设恒星，从近黑洞区域一直分布到观测边界附近；它们沿只由黑洞决定的解析圆轨道运行，恒星之间互不施力，也不响应卫星。

为同时保留原引力参数 `μ=2000000、r_s=66` 的轨迹和科学单位，使用 `L=r_s真实/66`、`T=sqrt(μ×L³/GM真实)` 换算。每场景单位约 **0.447462 km**，每模拟秒约 **0.000367446 s 模型物理时间**，每场景速度单位约 **1217.76272 km/s**。后台每现实秒推进1模拟秒，因此相当于慢放约 **2721 倍**，不是实时天体钟；服务器生存时间继续用模拟秒保存，同时附物理时间换算。积分步长保持1/240模拟秒。新发射卫星使用 `multi-attractor-pw-v1`：黑洞采用有限质量 PW 近似，恒星采用带近距软化的牛顿引力，所有加速度叠加。历史双体和测试粒子记录继续使用原力场，不改写既有轨迹。

初始半径允许约 **35.8 km–4.4746亿 km**；初速度必须有限、非负且小于光速；新版多引力源请求允许质量 (0, 10³⁰] kg，旧版请求仍保持原有 (0, 10¹²] kg 限制。页面提供 **0.00001%–6400% 对数缩放**、滚轮缩放、发射点/所选卫星定位与自动扩展视野；投影后的距离圈和1/2/5刻度尺标注世界平面的km距离，不把倾斜后的屏幕像素直接冒充距离。控制台黑洞艺术图的阴影按模型视界半径缩放，光环与吸积盘仍为美术效果。

控制台卫星光晕不保留最小屏幕尺寸：缩小视野时半径随投影尺度缩小，低于像素分辨率后按覆盖率减弱直至不绘制。尾迹线宽、亮度和选中标记同步变化；使用普通透明度合成，避免卫星叠加增亮成球。远景仍可通过列表、定位和速度面板查看对象；十字与箭头属于发射辅助标记。

新发射的正式卫星不会在预设逃逸半径停止或消失；启动时仍活跃的旧卫星也扩展为持续追踪。只有捕获、主动终止或数值异常会结束新卫星的轨迹。旧版已经以 escaped 结束的档案不重写；星图显示其最后位置，列表保留原终态。

后台持续保存 `vx/vy` 速度分量和状态，当前查询、历史查询、JSON及CSV导出附速度大小、km/s分量和距离。CSV保留原场景数值列，新增 `elapsed_physical_seconds、x_km、y_km、vx_km_s、vy_km_s、radius_km、speed_km_s、physical_speed_valid`。JSON每采样点附 `speed、speedKmS、physicalSpeedValid` 等字段，元数据含 `calibration`。新SI出生档案固定保存标定版本；旧记录按示例标定推算时明确标为 `calibrationInferred=true`，不修改旧轨迹。

**科学适用边界：** Paczyński–Wiita模型是伪牛顿近似，不是广义相对论求解器；标定SI单位并不使它成为精确的真实黑洞模型。速度读数为近似模型的坐标速度；高速和近视界需要相对论修正，模型甚至会给出超光速数值。此时页面显示“超出物理适用范围”，导出保留该模型数值并明确 `physicalSpeedValid=false`，不可当作真实速度。不给结果强行截成光速以伪造轨迹一致性。

预览限60模拟秒，不作为后台记录。新的 `time-linear-error-v1` 采样器以最多240次积分的一秒块检查按时间线性插值的误差：位置向量误差≤0.1 km，默认速度向量误差≤`max(0.1 km/s, 原始速度大小×0.001)`。选择的每一段都对全部中间积分点验证，保留精确端点、出生、终态和导出截止；搜索不保证最少点数。每次检查点也提交未满块的精确端点与完整恢复状态。误差保证只相对于原始240 Hz积分时刻，并不是连续时间或真实物理误差保证。设置环境变量 `ORBITAL_VELOCITY_RELATIVE_TOLERANCE=0` 可使新记录采用固定0.1 km/s严格速度误差；允许范围0–0.01，默认0.001（0.1%）。每颗卫星固定保存自己的采样配置，重启修改配置仅影响新卫星和首次升级的旧活跃卫星，不改变已采用新采样器的对象。严格模式在高速轨道上可能明显增加记录量。

旧点不重新简化，活跃旧档案以 `sampling.legacyThroughSeq` 标记旧政策边界，导出同时披露旧采样政策；旧终态档案继续披露原采样规则（一秒基础间隔、4r_s内每步、线性预测误差0.5场景单位加密）。回放速度由已记录速度分量插值得到。测试中半径80、切向场景速度1000的一秒积分位置与16倍细步长相差约0.352场景单位；径向捕获时间误差小于0.002模拟秒。这些是已测工况的误差，不能当作全参数保证。

相同240 Hz轨迹对照旧采样规则：半径100近轨道364→71点，半径330两圈229→214点，半径2000远轨道386→386点，径向捕获38→33点。默认模式的已测最大位置重建误差约0.09697 km，速度误差符合逐点0.1%/0.1 km/s容差。节省取决于轨道，不把相对每一步积分的减少量当作相对旧程序的存储收益。

单位依据：[IAU 2015 Resolution B3](https://arxiv.org/abs/1510.07674)、[NIST光速常量](https://physics.nist.gov/cuu/Constants/Value/c.html)。模型及速度限制依据：[Abramowicz (2009)](https://arxiv.org/html/0904.0913v1)。

### 持久化、备份及部署

默认数据库：`data/orbital.sqlite`，导出文件：`data/exports/`，无损轨迹归档：`data/trajectories/`。设置 `ORBITAL_DATA_DIR` 可更换数据目录。数据库、WAL、恢复凭证和归档不会通过静态文件路由暴露。导出文件保留7天，完整已记录轨迹永久保留，可重新导出。

后台每秒尝试归档一个最多4096点的块，将早于世界时钟24小时（86400模拟秒）的点压缩为不可变gzip文件；归档按已实际计算的世界时钟推进。文件fsync、原子发布及SHA-256校验成功后，同一SQLite事务提交manifest并移除对应热行。读取按序号拼接冷、热记录；归档失败保留源行并在 `/health.storage.archiveError` 报告。归档释放的SQLite页会被后续写入复用，数据库文件不会立即自动缩小；不自动删除归档文件。备份必须包含归档文件，不能只保留主数据库。

实时SSE初次发送完整档案，后续只发送变更状态；所选对象最高5Hz，其余对象最高1Hz，出生与终态立即发送。导出按2000点分页读取固定 `cutoffSeq`，每页释放SQLite读取事务再写文件，避免慢导出长时间阻挡WAL检查点。`/health.storage` 提供进程内原始步数、保留点数、缓冲状态数量、待写点数、检查点耗时、归档点数与DB/WAL大小；计数重启归零，并非并发容量保证。

```powershell
npm test
npm run backup
# 或指定一个尚不存在的备份目标
node server/backup.js D:\Codex\orbital\backups\manual.sqlite
```

备份使用 SQLite 在线备份 API 并执行 integrity_check，同时将快照manifest引用的归档校验后复制到 `<备份文件>.trajectories/`，全部完成后才发布备份数据库。恢复时先停止服务，把备份作为一个**新的空数据目录**中的 `orbital.sqlite`，并将配套 `.trajectories` 目录复制为该新目录中的 `trajectories/`，再把 `ORBITAL_DATA_DIR` 指向该目录启动；不要把备份直接覆盖到仍运行的数据库或残留WAL上。升级前没有归档的旧备份无需配套目录。恢复后从备份进度继续运行，不计算备份之后的离线时间。

提供 Dockerfile / compose.yaml：`docker compose up -d --build`，数据保存在持久化卷，配置为异常自动重启，默认只绑定主机127.0.0.1。此配置文件已提供，但尚未在本机执行 Docker 部署。公网部署需自行配置 HTTPS 反向代理，并将 `PUBLIC_ORIGIN` 设置为准确的外部源；生产服务应监控 `/health`、磁盘、备份和模拟落后时间。

本地预览不等于已部署到云端；电脑关闭后不会继续实时计算。系统时钟异常会停止推进并显示 clock_error，校准时钟后重启。

### 文件职责

`shared/units.js` 为共享科学标定和速度换算；`shared/simulation.js` 为正式物理核心；`server/trajectory-sampler.js` 控制记录误差；`server/trajectory-store.js` 负责冷、热轨迹和无损归档；`server/engine.js` 为单写者数据与模拟状态；`server/simulation-worker.js` 驱动固定步长；`server/index.js` 提供接口、身份与SSE；`server/stream-snapshot.js` 生成轻量增量；`server/export-worker.js` 分页流式生成导出；`shared/history-window.js` 为有界回放读取与插值；`map-3d.html/css/js` 和 `flight-controls-3d.js` 为控制台；`preview-worker.js` 为本地预测。

### 多引力源、自动名称和跟踪视角（2026-09-27）

新控制台发射请求附 `dynamicsVersion: "multi-attractor-pw-v1"`。每颗卫星独立接受中心黑洞与九颗预设恒星的叠加引力；不存在卫星间引力，恒星之间也不相互作用。恒星位置由全局模拟时钟和解析圆轨道唯一确定，因此服务器积分、短时预测、实时画面与历史回放使用相同星相。卫星穿过黑洞捕获面或任一恒星碰撞半径时结束，事件记录撞击天体和位置。

由Newton双体相对运动中的 `G(M+m)`（[MIT双体运动讲义](https://ocw.mit.edu/courses/16-346-astrodynamics-fall-2008/resources/lec_01/)）构造有限质量PW对势的近似黑洞项：`mu_eff = mu × (1 + m/M)`，`a = -mu_eff r_vector / [r(r-r_s)^2]`。这是本项目的近似选择，并非该Newton讲义给出的相对论公式。黑洞质量由标称GM和 `G=6.67430×10^-11 m³ kg^-1 s^-2`（[NIST](https://www.nist.gov/how-do-you-measure-it/how-do-you-measure-strength-gravity)）换算，视界半径与单位标定不变；恒星项使用带软化长度的Newton引力。页面给出的圆轨道/逃逸速度仅是黑洞单体参考，正式预览、后台积分和能量计算会叠加全部引力源，状态和导出保存参数与动力学版本。

新模型允许 `0 < m ≤ 10^30 kg`（约中央质量的5%），支持科学计数法，以便观察有限质量效应；此上限为实验输入限制，不是物理边界。普通卫星的真实质量效应极小，甚至低于浮点分辨率，不能人为放大。大质量和近视界结果仍不是广义相对论双体解。未指定新动力学版本的旧客户端保持原质量上限和原模型，历史活跃和终态均不静默迁移。

名称留空时，服务器生成 `SAT-` 加 `SHA-256(出生创建时间戳:卫星UUID)` 的前16位；UUID避免同毫秒重名。实际名称与命名时间戳持久化，幂等重试返回同一名称。发射面板可填自定义名称，最多64字符。

点击星图中的可见卫星或列表条目即持续跟踪，保持当前缩放；自动扩展视野与跟踪互斥。跟踪时缩放围绕卫星，回放也可跟踪对应历史位置；结束后停在最后位置。点击「退出跟踪」、拖拽/方向键平移、定位或重置可退出。远景不可见卫星可通过列表选中，图形仍按尺度淡出，不添加固定尺寸亮球。


### 恒星光球与近景观察（2026-11-05）

正式星图采用共享 WebGL 程序绘制恒星的光球颗粒、边缘渐暗和动态日冕。经典地图的恒星显示直径约为黑洞阴影直径的 1/4.2–1/9.2，与镜头保持线性缩放。恒星和行星在星图中以自身颜色区分，定位菜单用编号区分。

星图上方的「天体定位」可按编号定位并持续跟随恒星。远景用彩色点显示恒星位置，放大时逐渐过渡到光球表面；滚轮和缩放滑杆支持放大至 6400%。平移、重置或跟踪卫星后退出恒星特写。服务只推进实际运行期间的模拟时间，回放使用历史世界时钟。WebGL 不可用或上下文丢失时回退为 Canvas 光球，恢复后继续显示细节。

`stellar-renderer.js` 负责共享恒星材质、可见区域裁剪、透明合成与上下文恢复；`orbital-visuals.js` 保留黑洞并提供恒星显示比例和兼容绘制。


### 运行时间与停机（2026-11-05）

模拟时钟只累计服务实际完成的积分步数。停机、重启和恢复备份均保留已保存的世界 tick、星相与卫星状态，不再按系统时间差补算。调度器按单调时钟推进，单次最多接收 0.1 秒；休眠或卡顿期间未完成的整步不形成后续积压。固定积分步长仍为 1/240 模拟秒。

新卫星在当前世界 tick 立即出生，不再等待离线轨迹。旧版本保存为 queued 的卫星会在启动时一次性补全出生记录并进入运行；已记录的旧轨迹不改写。`/health` 的 `clockMode` 为 `runtime-only-v1`，正常运行时 `status=running、lagSeconds=0`。系统启动时仍保留时钟回退检查。
