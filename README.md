### Windows 双击启动

项目根目录提供 `ORBITAL.exe`。双击后会检查本机服务：若服务已经运行则直接打开任务页面；否则自动查找 `D:\node\node.exe`、项目内 `node.exe` 或 PATH 中的 Node，在后台启动服务，健康检查通过后打开浏览器。启动失败时会弹出原因，后台日志保存在 `data/server.launcher.log`。

启动器必须保留在项目根目录。修改启动器源码后，可在 PowerShell 中运行 `tools\build-launcher.ps1` 重新生成；`ORBITAL.exe --check` 仅检查项目结构和 Node，`ORBITAL.exe --no-browser` 启动服务但不打开浏览器。

- 恢复原视觉演示的三层旋转吸积盘、下落尘埃、光子亮斑和卫星发光尾迹；服务器捕获事件触发吞噬闪光、扩散光波和碎光，历史回放到捕获时也有对应效果。观察暂停只冻结画面。
- 左侧填写坐标、质量、初速度和方向，右侧同步显示十字定位及方向箭头；点击星图只选点，正式发射才创建卫星。
- 访客身份通过 HttpOnly 会话保存。首次出现的恢复密钥可下载保存，跨设备恢复档案；也可主动轮换密钥。密钥持有者可以访问和终止该身份的卫星，请私密保存。
- SQLite 保存出生档案、轨迹、关键事件与恢复状态。关闭浏览器后仍运行；本机服务或电脑停止时暂停实际计算，下次启动按经过时间补算，落后时显示恢复进度。

- 实时画面最多绘制最近 100 个对象并保留当前选中对象；较老的对象可分页选择并继续订阅。回放提供完整生命时间轴，按需读取当前位置附近最多20模拟秒的窗口，缓存上限8000点；导出不受显示窗口限制。
- 后台初始容量保护为 1000 个并发活跃/排队对象，可通过 `ORBITAL_MAX_ACTIVE` 配置；不限制累计发射次数。达到容量时明确拒绝新请求，保留已有轨迹。正式容量取决于硬件和采样密度，需要实测调整。

### 时间、单位和误差

正式控制台输入采用 **km、km/s、kg**，坐标以黑洞中心为原点、世界坐标 +Y 向上。明确假设中央黑洞质量为 **10 倍标称太阳质量**，不是对某个实测黑洞的标定。由 IAU 2015 B3 的标称太阳质量参数 `(GM)☉ = 1.3271244×10²⁰ m³/s²` 和光速 `c = 299792458 m/s`，按 `r_s = 2GM/c²` 得到视界半径约 **29.5325 km**。

为同时保留原引力参数 `μ=2000000、r_s=66` 的轨迹和科学单位，使用 `L=r_s真实/66`、`T=sqrt(μ×L³/GM真实)` 换算。每场景单位约 **0.447462 km**，每模拟秒约 **0.000367446 s 模型物理时间**，每场景速度单位约 **1217.76272 km/s**。后台每现实秒推进1模拟秒，因此相当于慢放约 **2721 倍**，不是实时天体钟；服务器生存时间继续用模拟秒保存，同时附物理时间换算。积分步长保持1/240模拟秒。新发射卫星使用独立的有限质量双体相对运动，质量进入积分；历史未标记dynamicsVersion的记录继续使用测试粒子模型，不改写既有轨迹。

初始半径允许约 **35.8 km–4.4746亿 km**；初速度必须有限、非负且小于光速；质量 (0, 10¹²] kg。页面提供 **0.00001%–200% 对数缩放**、滚轮缩放、发射点/所选卫星定位与自动扩展视野；投影后的距离圈和1/2/5刻度尺标注世界平面的km距离，不把倾斜后的屏幕像素直接冒充距离。控制台黑洞艺术图的阴影按模型视界半径缩放，光环与吸积盘仍为美术效果。

控制台卫星光晕不保留最小屏幕尺寸：缩小视野时半径随投影尺度缩小，低于像素分辨率后按覆盖率减弱直至不绘制。尾迹线宽、亮度和选中标记同步变化；使用普通透明度合成，避免卫星叠加增亮成球。远景仍可通过列表、定位和速度面板查看对象；十字与箭头属于发射辅助标记。

新发射的正式卫星不会在预设逃逸半径停止或消失；启动时仍活跃的旧卫星也扩展为持续追踪。只有捕获、主动终止或数值异常会结束新卫星的轨迹。旧版已经以 escaped 结束的档案不重写；星图显示其最后位置，列表保留原终态。旧本地主页演示仍采用原清理规则，以下原始演示说明仅适用于该演示。

后台持续保存 `vx/vy` 速度分量和状态，当前查询、历史查询、JSON及CSV导出附速度大小、km/s分量和距离。CSV保留原场景数值列，新增 `elapsed_physical_seconds、x_km、y_km、vx_km_s、vy_km_s、radius_km、speed_km_s、physical_speed_valid`。JSON每采样点附 `speed、speedKmS、physicalSpeedValid` 等字段，元数据含 `calibration`。新SI出生档案固定保存标定版本；旧记录按示例标定推算时明确标为 `calibrationInferred=true`，不修改旧轨迹。

**科学适用边界：** Paczyński–Wiita模型是伪牛顿近似，不是广义相对论求解器；标定SI单位并不使它成为精确的真实黑洞模型。速度读数为近似模型的坐标速度；高速和近视界需要相对论修正，模型甚至会给出超光速数值。此时页面显示“超出物理适用范围”，导出保留该模型数值并明确 `physicalSpeedValid=false`，不可当作真实速度。不给结果强行截成光速以伪造轨迹一致性。

预览限60模拟秒，不作为后台记录。新的 `time-linear-error-v1` 采样器以最多240次积分的一秒块检查按时间线性插值的误差：位置向量误差≤0.1 km，默认速度向量误差≤`max(0.1 km/s, 原始速度大小×0.001)`。选择的每一段都对全部中间积分点验证，保留精确端点、出生、终态和导出截止；搜索不保证最少点数。每次检查点也提交未满块的精确端点与完整恢复状态。误差保证只相对于原始240 Hz积分时刻，并不是连续时间或真实物理误差保证。设置环境变量 `ORBITAL_VELOCITY_RELATIVE_TOLERANCE=0` 可使新记录采用固定0.1 km/s严格速度误差；允许范围0–0.01，默认0.001（0.1%）。每颗卫星固定保存自己的采样配置，重启修改配置仅影响新卫星和首次升级的旧活跃卫星，不改变已采用新采样器的对象。严格模式在高速轨道上可能明显增加记录量。

旧点不重新简化，活跃旧档案以 `sampling.legacyThroughSeq` 标记旧政策边界，导出同时披露旧采样政策；旧终态档案继续披露原采样规则（一秒基础间隔、4r_s内每步、线性预测误差0.5场景单位加密）。回放速度由已记录速度分量插值得到。测试中半径80、切向场景速度1000的一秒积分位置与16倍细步长相差约0.352场景单位；径向捕获时间误差小于0.002模拟秒。这些是已测工况的误差，不能当作全参数保证。

相同240 Hz轨迹对照旧采样规则：半径100近轨道364→71点，半径330两圈229→214点，半径2000远轨道386→386点，径向捕获38→33点。默认模式的已测最大位置重建误差约0.09697 km，速度误差符合逐点0.1%/0.1 km/s容差。节省取决于轨道，不把相对每一步积分的减少量当作相对旧程序的存储收益。

单位依据：[IAU 2015 Resolution B3](https://arxiv.org/abs/1510.07674)、[NIST光速常量](https://physics.nist.gov/cuu/Constants/Value/c.html)。模型及速度限制依据：[Abramowicz (2009)](https://arxiv.org/html/0904.0913v1)。

### 持久化、备份及部署

默认数据库：`data/orbital.sqlite`，导出文件：`data/exports/`，无损轨迹归档：`data/trajectories/`。设置 `ORBITAL_DATA_DIR` 可更换数据目录。数据库、WAL、恢复凭证和归档不会通过静态文件路由暴露。导出文件保留7天，完整已记录轨迹永久保留，可重新导出。

后台每秒尝试归档一个最多4096点的块，将早于世界时钟24小时（86400模拟秒）的点压缩为不可变gzip文件；计算落后时先补算。文件fsync、原子发布及SHA-256校验成功后，同一SQLite事务提交manifest并移除对应热行。读取按序号拼接冷、热记录；归档失败保留源行并在 `/health.storage.archiveError` 报告。归档释放的SQLite页会被后续写入复用，数据库文件不会立即自动缩小；不自动删除归档文件。备份必须包含归档文件，不能只保留主数据库。

实时SSE初次发送完整档案，后续只发送变更状态；所选对象最高5Hz，其余对象最高1Hz，出生与终态立即发送。导出按2000点分页读取固定 `cutoffSeq`，每页释放SQLite读取事务再写文件，避免慢导出长时间阻挡WAL检查点。`/health.storage` 提供进程内原始步数、保留点数、缓冲状态数量、待写点数、检查点耗时、归档点数与DB/WAL大小；计数重启归零，并非并发容量保证。

```powershell
npm test
npm run backup
# 或指定一个尚不存在的备份目标
node server/backup.js D:\Codex\orbital\backups\manual.sqlite
```

备份使用 SQLite 在线备份 API 并执行 integrity_check，同时将快照manifest引用的归档校验后复制到 `<备份文件>.trajectories/`，全部完成后才发布备份数据库。恢复时先停止服务，把备份作为一个**新的空数据目录**中的 `orbital.sqlite`，并将配套 `.trajectories` 目录复制为该新目录中的 `trajectories/`，再把 `ORBITAL_DATA_DIR` 指向该目录启动；不要把备份直接覆盖到仍运行的数据库或残留WAL上。升级前没有归档的旧备份无需配套目录。恢复后会从备份进度补算。

提供 Dockerfile / compose.yaml：`docker compose up -d --build`，数据保存在持久化卷，配置为异常自动重启，默认只绑定主机127.0.0.1。此配置文件已提供，但尚未在本机执行 Docker 部署。公网部署需自行配置 HTTPS 反向代理，并将 `PUBLIC_ORIGIN` 设置为准确的外部源；生产服务应监控 `/health`、磁盘、备份和模拟落后时间。

本地预览不等于已部署到云端；电脑关闭后不会继续实时计算。系统时钟异常会停止推进并显示 clock_error，校准时钟后重启。

## 轨道模型与时间尺度

采用非旋转中心天体的 Paczyński–Wiita 伪牛顿势：

`Phi(r) = -GM/(r-rs)`

`a = -GM * r_vector / [r*(r-rs)^2]`

`v_circular = sqrt(GM*r)/(r-rs)`，`v_escape = sqrt(2*GM/(r-rs))`。

参数为场景无量纲单位：`GM=2000000`、`rs=66`。掠入初速度取圆轨道速度的 0.5 倍，环绕取 1 倍，逃逸取逃逸速度的 1.1 倍，方向均为初始位置的切线方向。环绕选项在 `r>3rs` 的稳定区域可形成稳定圆轨道；近中心不能保证稳定。长按仅改变发光星体尺寸，不改变测试粒子的加速度或初速度。

使用固定 `1/240` 模拟秒步长的 kick-drift-kick / velocity Verlet 积分。捕获面设在 `1.05rs`，避免势的奇点；逐步检查运动线段是否越过捕获面，避免高速粒子穿越后反弹。正能量、向外运动且离开 `r=max(1200, 初始半径×3)` 的星体计作逃逸；此清理边界在投放时确定，不随镜头改变，远距离发射不会立刻消失。每颗星只保留最近 70 个尾迹采样点。无固定寿命、无强制阻尼，不强制让稳定轨道衰减。

默认流速从 `1.0×` 降至 `0.3×`；背景吸积盘各层按本模型的圆轨道角速度变化，并乘 0.55 的视觉系数。镜头倾角固定，不再摇摆。近中心亮斑也同步减速。吸积盘纹理、向内移动的尘埃和吞噬光波是美术效果，不是流体求解。黑色遮罩半径 171 是视觉阴影示意，并非物理捕获半径；粒子即使被遮住，仍继续积分至捕获面。

这不是完整的广义相对论模拟：未计算光线弯曲、红移、时间膨胀、黑洞自旋或粒子间相互引力。伪牛顿速度也不具备严格的相对论速度上限。真实变化快慢取决于黑洞质量、轨道尺度和观察方式，本页面未标定太阳质量或真实秒数；“0.3×”仅为演示时间倍率。

模型依据：[Abramowicz (2009), The Paczyński-Wiita potential](https://arxiv.org/html/0904.0913v1)。数值校验：`node --test physics.test.cjs camera.test.cjs`，涵盖远场反平方极限、稳定圆轨道、守恒量、捕获、逃逸、质量无关性、帧率一致性和捕获面穿越。

本项目为虚构设计体验，页面中的旅行景观和航线并非真实服务。

## 视野缩放

使用独立的「视野缩放」滑杆（10%–200%）、减号/加号或复位按钮。缩至 10% 后，屏幕上同一位置距黑洞的场景距离为原来的 10 倍；点击星空和投星按钮均按当前视角计算初始位置。黑洞、星体与轨迹共用 `camera.js` 的投影，不改变已有星体的速度、位置或模拟时间。远处运行较慢，可另调时空流速。缩小后选择「环绕」并在黑洞外投放，可观察远距离圆轨道；掠入模式也可能形成不被捕获的偏心轨道。

缩放和复位支持键盘；暂停时仍可调视角。发光点保留最小屏幕尺寸，方便在广视野中辨认。坐标变换测试覆盖手机/桌面、缩放极限和十倍投放距离。


### 控制台准星与鼠标缩放

发射定位准星采用0.75像素半透明虚线，中心留空；方向箭头也变细、缩短并使用虚线。滚轮以当前鼠标位置为缩放锚点，光标下的世界坐标保持不变；滑杆使用鼠标最近在星图中的位置，没有该位置时以画面中心缩放。定位与重置会重新居中；自动扩展视野保持黑洞居中的观察方式。视角平移和缩放共用正反坐标投影，不修改后台轨迹。


### 控制台黑洞标识与拖拽

黑洞中心保留固定大小的辅助标识，不随物理图形缩放而消失；中心离开可用视野时，边缘显示指向黑洞的箭头。点击标识可将黑洞居中，并保持当前缩放。星图支持鼠标按住拖动和单指触控平移，单击仍选择发射坐标；移动超过6像素才视为拖拽，拖拽结束不会误触选点。聚焦星图后可用方向键平移，Shift加快。手动平移或缩放会退出自动扩展视野，后台积分与记录不受影响。


### 星图鼠标模式

星图上方新增「拖拽星图 / 选择发射点」按钮，当前模式高亮，默认选择发射点。选点模式单击回填左侧坐标；拖拽手势不会选点或移动视野。拖拽模式只平移，不回填坐标。两个模式均支持鼠标锚点滚轮缩放与方向键平移。选点完成后使用左侧「正式发射」创建卫星。此模式规则取代上一节的拖拽与单击共用操作。


### 独立双体质量、自动名称和跟踪视角（2026-09-17）

新控制台发射请求附 `dynamicsVersion: "two-body-pw-v1"`。每颗卫星视为一组独立的黑洞—卫星双体实验，位置和速度均相对本组黑洞；不存在卫星间引力或通过共享黑洞产生的间接耦合。黑洞图形保持作为坐标原点。

由Newton双体相对运动中的 `G(M+m)`（[MIT双体运动讲义](https://ocw.mit.edu/courses/16-346-astrodynamics-fall-2008/resources/lec_01/)）构造有限质量PW对势的近似扩展：`mu_eff = mu × (1 + m/M)`，`a = -mu_eff r_vector / [r(r-r_s)^2]`。这是本项目的近似选择，并非该Newton讲义给出的相对论公式。黑洞质量由标称GM和 `G=6.67430×10^-11 m³ kg^-1 s^-2`（[NIST](https://www.nist.gov/how-do-you-measure-it/how-do-you-measure-strength-gravity)）换算，视界半径与单位标定不变。预览、积分、圆轨道/逃逸速度参考和能量使用同一个有效参数，状态和导出保存参数与版本。

新模型允许 `0 < m ≤ 10^30 kg`（约中央质量的5%），支持科学计数法，以便观察有限质量效应；此上限为实验输入限制，不是物理边界。普通卫星的真实质量效应极小，甚至低于浮点分辨率，不能人为放大。大质量和近视界结果仍不是广义相对论双体解。未指定新动力学版本的旧客户端保持原质量上限和原模型，历史活跃和终态均不静默迁移。

名称留空时，服务器生成 `SAT-` 加 `SHA-256(出生创建时间戳:卫星UUID)` 的前16位；UUID避免同毫秒重名。实际名称与命名时间戳持久化，幂等重试返回同一名称。左侧可填自定义名称，最多64字符。

点击星图中的可见卫星或列表条目即持续跟踪，保持当前缩放；自动扩展视野与跟踪互斥。跟踪时缩放围绕卫星，回放也可跟踪对应历史位置；结束后停在最后位置。点击「退出跟踪」、拖拽/方向键平移、定位或重置可退出。远景不可见卫星可通过列表选中，图形仍按尺度淡出，不添加固定尺寸亮球。
