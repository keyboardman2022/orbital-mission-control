# WebGL 精确历史轨迹设计

日期：2026-09-23  
状态：设计草案，等待用户确认  
适用项目：`D:\Codex\orbital`

## 1. 目标

历史回放加载当前卫星截至固定截止点的全部已保存轨迹，并使用 WebGL 精确绘制这些记录点。长时间回放不得再次对旧轨迹执行 6000 点全局抽稀，不得跨越缺失序号绘制假线，也不得让轨迹绘制阻塞现有 Canvas 动画。

“精确”指逐点使用数据库中已经保存的 `seq、tick、elapsedSeconds、x、y`。本功能不能恢复 240 Hz 积分中未保存的中间状态，也不能恢复单颗卫星达到约 100 MiB 上限后不再记录的轨迹。

## 2. 范围和约束

- 只替换历史轨迹线的加载、缓存和绘制方式。
- 黑洞、星空、卫星、冲击波、准星、距离网格和交互界面继续由现有 Canvas 2D 绘制。
- 继续使用现有 `/api/satellites/:id/trajectory` JSON 分页接口，不修改 SQLite、gzip 归档、导出格式或身份模型。
- 一次只加载当前选中卫星的完整轨迹。
- 浏览器内不再保留全部 JSON 对象；每页处理后写入紧凑数组并释放响应对象。
- 服务端轨迹上限仍为 409,600 个保存点。

## 3. 用户流程

1. 用户选择卫星并点击“加载历史回放”。
2. 页面立即进入历史模式，先用现有的小窗口查询加载出生点附近数据并固定回放截止序号，同时提供当前位置和速度插值。
3. 初始窗口成功后，从出生点开始分页读取同一截止序号下的完整轨迹。
4. 每页到达后追加到 CPU 紧凑数组和 GPU 缓冲，画面逐步补全已经加载的轨迹。
5. 状态区显示“已加载点数 / 截止点数”和百分比。加载完成后显示“完整精确轨迹”。
6. 播放时间轴时，WebGL 只绘制 `elapsedSeconds <= replayElapsed` 的已加载连续线段。
7. 返回实时、切换卫星、删除卫星或退出身份时，取消请求并释放 CPU、GPU 资源。

完整加载失败不影响当前窗口回放。页面保留已成功加载的前缀并显示错误，可由用户再次点击加载历史重试。

## 4. 数据读取与一致性

完整加载器使用现有分页接口，每页请求最多 5000 点：

- 初始局部窗口固定服务器返回的 `cutoffSeq` 和 `cutoffTick`；完整加载的第一页必须携带同一截止序号。
- 后续页始终携带相同 `cutoffSeq`，通过 `nextCursor` 继续读取。
- 重复或倒退的游标视为错误，避免无限循环。
- 相同 `seq` 只接收一次；序号必须严格递增。
- `seq` 不连续时记录新的绘制段，禁止把缺口两端连接起来。
- 返回的 `trajectoryCoverage` 若为 `capped`，时间轴终点保持在覆盖终点。
- 活跃卫星在加载期间继续运行，但本次回放只展示固定截止点之前的数据；重新加载历史会建立新的截止点。

完整加载器与局部窗口读取分别使用独立的 `AbortController`，避免播放跨窗口时取消完整加载；两者共享同一个身份、卫星选择和回放会话版本校验。清除历史时同时取消两个控制器，旧卫星或旧身份的迟到响应不得写入当前缓冲。

## 5. CPU 内存表示

每颗选中卫星使用分块紧凑数组，避免预先分配失败和频繁复制：

- `Float64Array x`
- `Float64Array y`
- `Float64Array elapsedSeconds`
- `Uint32Array seq`
- `Float64Array tick`

每块与一个成功读取的分页响应对应。409,600 点的核心字段约占 15 MiB；临时 JSON 每页处理完成后即可回收。段索引单独记录 `{start, count}`，只描述真实连续序号。

当前局部窗口继续保留完整 `vx、vy`，用于精确速度显示和插值。完整轨迹 GPU 层只需要位置、时间和连续性信息。

## 6. WebGL 渲染器

新增独立模块 `history-webgl.js`。它创建不挂载到页面的透明 WebGL 画布，在现有 `mission.js` 绘制历史轨迹的位置渲染，然后通过 Canvas 2D `drawImage` 合成到主画布。这样维持现有图层顺序：黑洞和网格在下，历史轨迹居中，卫星与HUD在上。

渲染器职责：

- 初始化、编译并校验最小顶点/片元着色器。
- 接收分页顶点并使用预分配缓冲和 `bufferSubData` 增量上传。
- 使用相机矩阵 uniform 完成平移、缩放、Y轴倾斜与屏幕映射；拖拽、缩放和跟踪不重新上传轨迹。
- 根据回放时间对每个连续段做二分查找，只提交可见前缀。
- 为每个连续段单独调用 `drawArrays(LINE_STRIP)`，任何序号缺口都不会生成线段。
- 输出透明背景、固定屏幕线宽和现有绿色轨迹颜色，再由主 Canvas 合成。

WebGL 顶点属性使用“高位 + 低位”两个 `float` 表示每个世界坐标。CPU 通过 `high = Math.fround(value)`、`low = value - high` 编码，着色器与同样拆分的相机原点做补偿减法，避免在远距离坐标下直接使用单精度导致明显抖动或错位。

WebGL 原生线宽在不同平台通常只能可靠保持 1 像素。第一版使用 1 像素 `LINE_STRIP`；若需要更粗线条，再以三角带扩展，不在本次范围内。

## 7. 上下文丢失与兼容

- 监听 `webglcontextlost`，阻止默认销毁流程并暂停精确轨迹层。
- 监听 `webglcontextrestored`，使用仍在 CPU 紧凑数组中的数据重建着色器和缓冲。
- 浏览器无法创建 WebGL 上下文时，明确显示“此浏览器不支持完整精确轨迹”，局部窗口回放仍可使用。
- 不回退到现有的 6000 点重复抽稀轨迹，避免再次产生已确认的错误连线。
- 页面隐藏时暂停不必要的 WebGL 绘制，恢复可见后继续。

## 8. 性能与资源边界

- GPU 初始容量依据卫星 `trajectoryCoverage.lastSeq`，最高不超过 409,600 点；缺失或异常值时按分页增长并设置同一硬上限。
- 顶点高低位坐标约占 16 字节/点，409,600 点约 6.25 MiB；CPU 核心数组约 13 MiB。
- 每个 JSON 页面最多 5000 点，避免一次构造全部历史对象。
- 每个动画帧只更新少量 uniform，并绘制当前时间之前的顶点；不再由 JavaScript 对全部轨迹逐点投影。
- 页面同时只保留一个完整历史轨迹。选择其他卫星时立即释放前一个 WebGL buffer。
- 如果完整加载速度受当前大量小型 gzip 归档影响，本次只记录测量结果，不修改归档结构。

## 9. 模块边界

`shared/history-window.js`：保留局部窗口、插值和分页一致性工具；移除历史回放对 `createTrail(6000)` 的依赖，但不影响实时卫星尾迹。

`history-webgl.js`：只负责紧凑数据、连续段索引、坐标高低位编码、GPU 生命周期和绘制。它不请求网络、不读取 DOM 表单、不控制播放状态。

`mission.js`：负责完整轨迹分页、取消、进度、回放时间和相机参数，把数据页传给 WebGL 渲染器，并把渲染结果合成到主 Canvas。

`mission.html`：加载新模块并更新静态资源版本号。第一版不增加新的按钮，现有“加载历史回放”触发完整轨迹加载。

## 10. 错误处理

- 页数据不是严格递增序号、包含非有限坐标或超过硬上限时，中止完整加载并显示错误。
- 分页失败保留已加载前缀，但标记为“不完整”，不得显示“完整精确轨迹”。
- 切换选择或身份后，旧请求即使返回也不得上传GPU或更新进度。
- GPU 初始化、着色器编译和缓冲分配错误必须转换为用户可读状态，不影响服务器计算。
- WebGL 上下文恢复失败时释放渲染器并继续提供局部窗口回放。

## 11. 验证

自动测试覆盖：

- 40万点按多页追加后全部保留，不进行6000点抽稀。
- 分页固定首次 `cutoffSeq`，拒绝重复游标和迟到响应。
- 连续序号形成同一绘制段，缺失序号形成新段，绘制范围不跨缺口。
- 时间轴前进和回退使用二分查找得到正确可见顶点数。
- 大世界坐标经高低位编码和相机相减后保持亚像素投影误差。
- 切换卫星、返回实时、删除和身份重置会取消请求并释放缓冲。
- WebGL 上下文丢失后不绘制，恢复后从 CPU 数组重建相同轨迹。
- WebGL 不可用时局部历史回放仍可操作并显示明确说明。

使用当前约390,606点的真实长轨迹进行浏览器验证：记录完整加载时间、峰值浏览器内存、静止回放帧率、跟踪视角帧率、拖拽与缩放响应，并目视确认出生、中段、末段没有横穿轨道的假线。

完成后运行现有全部自动测试，确认物理积分、数据库、归档、导出、删除记录和实时绘制不受影响。
