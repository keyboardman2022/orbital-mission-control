- 测试日期：2026-09-24
- 浏览器与版本：Microsoft Edge 147.0.0.0，无界面模式，ANGLE SwiftShader WebGL
- 轨迹点数：409,600 个真实保存点（验证开始时原约 390,606 点的长轨迹已继续增长并达到 100 MiB 记录上限）
- 固定 cutoffSeq：409,600
- 分页数量：82 页，每页最多 5,000 点
- 完整数据源读取时间：39.50 秒；服务并发执行离线补算时复测为 107.32 秒
- 浏览器 JSON 分页、TypedArray 写入及单层 GPU 上传时间：4.769 秒（数据已在本地验证服务内存中预载）
- JS heap：22,774,085 bytes，约 21.72 MiB
- 静止回放平均帧率：3.51 个完整 GPU 帧/秒
- 跟踪视角平均帧率：3.71 个完整 GPU 帧/秒
- 帧率说明：上述数字来自无硬件 GPU 的 SwiftShader，并在每帧执行 `gl.finish()`，是同步完成 409,600 点整条线的保守下限，不代表用户机器硬件加速后的显示刷新率。
- 连续段数量：1；409,600 个序号严格连续，没有发现缺口
- 大坐标投影误差：`1.4210854715202004e-14` CSS 像素
- 出生段目视结果：轨迹由真实保存点逐步形成多圈进动图案，没有跨轨道弦线或跳点连线
- 中段目视结果：密集椭圆进动结构连续，旧圈层没有错位、直角转弯或横穿图案的线
- 末段目视结果：全部 409,600 点形成连续的完整进动区域，没有全局抽稀造成的长直线
- 拖拽与缩放结果：同一 GPU 顶点缓冲通过相机 uniform 移动；自动测试确认相机变换不改变保存点，真实数据的 CPU/WebGL 投影误差低于 0.25 像素要求
- WebGL 上下文恢复结果：真实 Edge 上触发 `WEBGL_lose_context` 后依次收到 `lost`、`restored`，CPU 紧凑数组重新上传；自动测试同时覆盖恢复失败降级
- WebGL 不可用结果：局部窗口回放继续可用，页面显示“此浏览器不支持完整精确轨迹”
- 页面生命周期结果：返回实时、切换卫星、永久删除档案和身份清理会取消完整分页并释放轨迹缓冲；迟到响应不会写入新会话
- 服务健康结果：`GET /health` 返回 HTTP 200、`status: running`、`clockError: null`
- 全量自动测试结果：163/163 通过，0 失败，耗时 10.21 秒

## 结论与性能边界

WebGL 层逐点保留并绘制数据库已有的全部轨迹，不再使用 6,000 点重复抽稀。当前真实轨迹的视觉结构与序号连续性一致，出生、中段和末段未发现旧实现中的错误连线。

浏览器侧内存和数据写入处于设计范围内。完整读取的主要耗时来自现有 41,358 个小型 gzip 归档文件；并发离线补算时读取明显变慢。这次按既定范围没有修改归档结构，页面会持续显示精确点数和百分比，已经加载的前缀可立即绘制。
